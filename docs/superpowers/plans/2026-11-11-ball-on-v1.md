# Ball On v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Ball On Learner app and Review build (an offline web app for snooker referee revision), plus the Options List and the first two Topics of Draft Questions for Rani to review.

**Architecture:** A static TypeScript app with no UI framework. Pure domain modules (marking, scheduling, drill selection) are kept separate from DOM screens. Questions live in JSON files under `questions/`. A prebuild script validates them and writes a per-build bank, which is how the Learner build physically excludes Drafts. Progress lives in `localStorage` under a per-build key.

**Tech Stack:** TypeScript (strict), Vite, Vitest + happy-dom, vite-plugin-pwa, GitHub Actions → GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-11-11-ball-on-design.md`; vocabulary in `CONTEXT.md`; decisions in `docs/adr/0001`–`0005`. Read all three before starting.

## Global Constraints

- No UI framework, no backend, no network calls at runtime, and no analytics.
- Never commit `docs/source/` (WPBSA copyright). Never paste Rulebook wording into questions, explanations or code comments. Paraphrase it and cite the rule.
- Rulebook edition id: `"2024-09"`. Every Question has `edition: "2024-09"`.
- Rule Citation format: `S<section> R<rule>` followed by optional `(a)`-style and `(iv)`-style parts, e.g. `S3 R14(d)(ii)`. Highest rule number per Snooker section: S1 4, S2 22, S3 21, S4 7, S5 4.
- The Learner build must contain zero Draft Questions in its output files (not just hidden).
- Storage keys: `ball-on:learner:v1` and `ball-on:review:v1`. Both builds share the `*.github.io` origin.
- Base paths: Learner `/ball-on/`, Review `/ball-on/review/`.
- UI copy uses the CONTEXT.md terms (Drill, Ruling, Call, Options, Flag, Draft, Reviewed, Judgement Call). Never "quiz", "card" or "user".
- Phone-first: usable one-handed at 360px wide; tap targets ≥ 44px; works in light and dark mode.
- Strict marking everywhere except Judgement Calls (ADR 0003).

## Review Focus

1. **The Learner app has zero Reviewed Questions on day one** (everything starts as a Draft). Home must show a clear "No reviewed questions yet" state, not a crash or an empty Drill. → test in Task 8.
2. **Both builds on one `github.io` origin**: the Review build's progress and verdicts must never leak into Learner progress. → per-build key test in Task 5.
3. **Corrupt, old or foreign data in `localStorage` or an import file**: the app starts with empty progress and doesn't crash, and an import is rejected with a message, leaving current data unchanged. → tests in Task 5.
4. **`navigator.share` missing (desktop browsers) or cancelled by the Learner**: fall back to the clipboard, and treat a cancel as a non-error. → tests in Task 6.
5. **Progress referencing a Question that no longer exists** (removed or renamed id after review): ignored by the Drill, never shown. → test in Task 4.

### Task 4: Scheduler and Drill selection

**Files:** Create `src/domain/scheduler.ts`, `src/domain/drill.ts`, `tests/domain/scheduler.test.ts`, `tests/domain/drill.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export interface ReviewState { box: number; due: number; seen: number }   // epoch ms
  export const INTERVALS_DAYS = [1, 3, 7, 14, 30] as const;                  // box 1..5
  export const RELEARN_MS = 10 * 60 * 1000;
  export function schedule(prev: ReviewState | undefined, correct: boolean, now: number): ReviewState
  export const DRILL_SIZE = 10; export const MAX_NEW_PER_DRILL = 3;
  export function buildDrill(questions: Question[], progress: Record<string, ReviewState>, now: number, rng?: () => number): Question[]
  export function topicSession(questions: Question[], topic: string, rng?: () => number): Question[]
  ```
- Rules:
  - `schedule`:
    - wrong → `{box: 1, due: now + RELEARN_MS}`
    - right on a new question → box 1, due in 1 day
    - right otherwise → `box = min(prev.box + 1, 5)`, `due = now + INTERVALS_DAYS[box-1] days`
    - `seen = now`
  - `buildDrill`:
    - only `scenario` and `recall` questions
    - Due ones (`due <= now`) first, most overdue first
    - then fill up to `DRILL_SIZE` with new questions (no progress), at most `MAX_NEW_PER_DRILL` of them unless nothing is Due, in which case up to `DRILL_SIZE` new
    - the drill may be shorter than 10; never pad with questions that aren't Due
    - progress keys with no matching question are ignored
  - `topicSession`: every question in the Topic, shuffled, with Judgement Calls placed last.

  - right in box 5 stays in box 5 with a 30-day interval
  - 12 Due + 5 new → 10 Due, 0 new
  - 2 Due + 20 new → 2 + 3
  - 0 Due + 20 new → 10 new
  - every question seen and nothing Due → `[]`
  - a Judgement Call is never in a Drill
  - a progress entry for `'gone-001'` is ignored (Review Focus 5)
